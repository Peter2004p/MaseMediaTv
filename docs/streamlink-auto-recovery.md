# MaseNet automatic streamlink recovery

This feature is additive and is intentionally isolated from the existing Telegram Bot API webhook and title catalogue.

## What it does

1. A scheduled GitHub Actions job asks the protected Pages Function for the currently saved movie/drama stream variants.
2. It checks each direct HTTPS URL with HEAD (and a one-byte Range GET fallback where HEAD is unsupported).
3. Only a repeated HTTP 404 or 410 is treated as confirmed expiry. Network failures, timeouts, 401/403, redirects and 5xx responses are inconclusive and never trigger replacement.
4. For a confirmed expired variant, a separate Telegram MTProto user session opens the configured KDL Air bot, selects the same quality and episode, presses Generate Streamlink, and reads the generated URL.
5. The runner verifies that the new filename still identifies the same quality and codec.
6. The protected Pages Function replaces only the exact old URL for the exact episode and quality/codec. A concurrent edit causes a 409 conflict rather than overwriting newer data.
7. Each successful replacement is recorded in `streamlink_recovery_history`.

The workflow never deletes a title, episode, poster, subtitle, or other quality. It does not treat Telegram's “file will be deleted in 5 minutes” warning as proof that the generated direct URL has expired.

## Important runtime requirement

Cloudflare Pages Functions can safely scan and update D1, but they cannot act as a logged-in Telegram user through the ordinary Telegram Bot API. The separate GitHub Actions runner uses GramJS/MTProto for the personal-account interaction. This avoids replacing or changing the existing MaseNet Stream Manager bot token or webhook.

The scheduled workflow is every 15 minutes. GitHub may delay scheduled workflows, so this is periodic recovery, not a guaranteed instant refresh. GitHub scheduled workflows run from the repository's default branch (`main` here), not from the Cloudflare production branch (`cloudflare-migration`). Automatic production recovery therefore requires the workflow to be merged into `main` and the protected Pages API to be released on `cloudflare-migration`. Before that, use `workflow_dispatch` on this feature branch with the preview URL and preview secret for staging tests.

## Required configuration

Configure the following values as GitHub Actions repository secrets (Settings → Secrets and variables → Actions → New repository secret):

- `MASETV_RECOVERY_URL`: the base URL of the MaseNet environment that has this API deployed, without a trailing slash (for example, the Pages preview URL for this branch during staging).
- `STREAMLINK_RECOVERY_SECRET`: a long random secret. Configure the exact same value as a Cloudflare Pages secret named `STREAMLINK_RECOVERY_SECRET` for that environment.
- `TELEGRAM_API_ID`: API ID from https://my.telegram.org.
- `TELEGRAM_API_HASH`: API hash from https://my.telegram.org.
- `TELEGRAM_SESSION`: the personal Telegram session string generated by the one-time bootstrap below.
- `KDL_AIR_BOT_USERNAME`: `KDLAirBot` (confirmed by the owner).

### Create the Telegram session once

Use a trusted local Node.js terminal or a private GitHub Codespace. Do not run this on a public/shared computer.

```bash
npm install telegram input
TELEGRAM_API_ID=your_api_id TELEGRAM_API_HASH=your_api_hash node scripts/create-telegram-session.mjs
```

The script asks for your phone number, the Telegram login code, and (if enabled) your 2-step verification password. It prints a session string. Store it immediately as the GitHub Actions secret `TELEGRAM_SESSION`, then clear the terminal output. Never commit the session string, paste it into ChatGPT, or share it with anyone. Revoke the session from Telegram Settings → Devices if it is ever exposed.

## Staging and activation

The Pages project's Preview D1 binding is isolated to the existing `masenet-asian-discovery-preview` database; production continues using its own D1 binding. The additive recovery-history migration has been applied to that Preview database only.

1. Apply migration `0004_streamlink_recovery.sql` to the isolated preview D1 database only.
2. Configure `STREAMLINK_RECOVERY_SECRET` as a Cloudflare Pages preview secret.
3. Add the GitHub Actions secrets above.
4. Set the preview URL in `MASETV_RECOVERY_URL`.
5. Run the workflow manually and inspect its logs. It must report “No confirmed expired links” or show a narrowly scoped successful replacement.
6. Test with a link that is known to be expired and a non-production title/episode before considering production activation.

Do not point the workflow at production until staging tests pass and the owner explicitly approves a production release.

## Known limitations / safety

- KDL Air's username is not visible in the supplied screenshot; the exact username must be configured.
- The bot's current button labels and callback behaviour can change. If the exact quality, season, episode, or Generate Streamlink button cannot be identified, the runner stops for that item and leaves the old URL untouched.
- A replacement is blocked if the generated filename does not identify the same quality and codec. If KDL Air does not expose codec-specific choices, this strict check may leave a link unreplaced rather than silently substituting a different encode.
- Some hosts deliberately return 403 to automated checks. 403 is inconclusive and is not treated as expiry.
- Telegram's account session is highly sensitive. Use a dedicated account if possible, enable 2-step verification, store the session only in GitHub Actions secrets, and revoke it if exposed.
- Use this only for streams that you are authorized to access and distribute.
