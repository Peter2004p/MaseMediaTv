# Cloudflare migration status and API contract

This is a staged migration branch. The live AppDeploy site has not been changed and Cloudflare Pages automatic deployment remains disabled.

## Implemented in the migration branch
- `GET /api/titles` and admin-only create/update/delete routes store the full frontend title object in D1 metadata.
- `GET/POST /api/broadcasts`, `GET/POST /api/homepage-settings`, and `GET/POST /api/site-theme`.
- Google OAuth admin login routes and server-side session checks; requires Cloudflare secrets and a matching Google OAuth redirect URI.
- Telegram Mini App `initData` signature validation; requires `TELEGRAM_BOT_TOKEN`.
- Telegram bot webhook title search and admin-only webhook setup; both require `TELEGRAM_BOT_TOKEN` and `TELEGRAM_WEBHOOK_SECRET`.
- AI assistant route currently provides Cloudflare-library search/fallback replies. It is not connected to a model provider yet.
- Admin-only media upload route and media retrieval routes are implemented against an optional `MEDIA_BUCKET` R2 binding.

## Required configuration / blockers
- Cloudflare R2 is not enabled for the account yet. Cloudflare's API currently returns error 10042 (“Please enable R2 through the Cloudflare Dashboard”). Until R2 is enabled and a `MEDIA_BUCKET` binding is attached to Pages, media uploads intentionally return HTTP 503 and no files are stored.
- Configure these as Cloudflare Pages secrets, never commit their values: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `ADMIN_EMAIL` (optional; default `pb5089780@gmail.com`), `TELEGRAM_BOT_TOKEN`, and `TELEGRAM_WEBHOOK_SECRET`.
- The Google OAuth client must allow the redirect URI `https://<the-final-pages-domain>/api/auth/google/callback`.
- AI model credentials or a Workers AI binding have not been configured; current assistant responses are not generated by a model.
- HLS proxying is implemented for registered episode URLs with same-origin manifest/segment rewriting and range forwarding, but it still needs live tests against actual provider URLs. MKV transcoding is not ported; the player may fail on MKV sources until a compatible transcoding service is available.

## Before cutover
1. Enable R2 in the Cloudflare dashboard, create a bucket, and attach it to the Pages project as `MEDIA_BUCKET`.
2. Configure the required secret bindings and Google OAuth redirect URI.
3. Deploy only to a preview environment first; test admin login, CRUD, uploads, subtitles, playback, and Telegram end to end.
4. Do not change the production Telegram webhook or direct traffic until preview tests pass. Keep AppDeploy available as rollback.
